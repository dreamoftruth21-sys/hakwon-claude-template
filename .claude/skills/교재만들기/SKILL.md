# 시험대비 교재 만들기

**구성은 반마다 다르다.** 무엇을 넣고 어떤 순서로 묶을지는 매번 그 반 기록으로 제안하고 강사 승인을 받아 정한다.
`공용/규칙/교재구성.md` 는 **세종예고2 기말 교재 1권 사례**다 — 제안할 때 "이런 사례가 있다"고 보여 주는 참고일 뿐, 그대로 옮기지 않는다.
이 스킬이 강제하는 것은 두 가지뿐이다: 아래 **짜는 순서**와 **품질 규칙**(`교재구성.md` 6-1).

반 폴더 안에서 쓴다. 반 폴더가 아니면 어느 반인지 먼저 묻는다.

## 1. 조사 — 만들기 전에 (여기서 멈추고 제안한다)

1. **범위** — 반 `CLAUDE.md` 「범위」. 교과서 본문만인지, 활동 지문 · 학평 번호가 정해졌는지. 범위 밖 지문은 한 쪽도 넣지 않는다
2. **지난 교재에서 실제로 쓴 것 · 안 쓴 것** — `수업일지.md` 로 확인한다(지난 시험 대비 기간 전체). 안 쓴 자료는 다시 넣지 않는다. 일지에 없으면 강사에게 묻는다
3. **학교 시험 형식** — 반 `분석/출제경향.md` (유형 비중 · 서술형 유무 · 원문 변형 방식 · 제목 · 선택지 꼴). 없으면 `시험지분석` 스킬부터
4. **직전 시험 결과 · 약점** — 출제경향의 직전 시험 장, 설문 · 피드백 기록. 약점 보완 자료의 근거가 된다
5. **쓸 수 있는 원본** — `학교자료/부교재/` · `공용/교재/` 에 무엇이 있는지, 각 자료의 단계 · 쪽수 · 범위 밖 쪽이 섞였는지 (쪽 지도를 뽑는다: 쪽마다 앞부분 글자와 범위 밖 낱말 수)
6. **수업 계획** — `시험대비/<시험>/수업계획.md` 의 남은 회차 · 진도 방식. 교재는 그 순서로 푸는 책이다

### 1-1. 구성 제안 — `시험대비/<시험>/교재구성_제안.md` 에 쓰고 멈춘다

- 부분마다 출처 · 들어갈 쪽 · 뺄 쪽(이유) · 예상 쪽수 · 쓰는 때(수업/숙제/날짜)
- **푸는 순서대로** 묶은 안을 기본으로 낸다(단계별) — 숙제를 "몇 쪽부터 몇 쪽까지"로 낼 수 있게. 자료 종류별 묶음은 강사가 원할 때만
- 직접 만들 부분(정리 자료 · 약점 보완 · 문제 세트)은 무엇을 몇 쪽 만들지와 그 근거(직전 시험 결과)를
- 정해야 할 것을 번호로 묻는다. **승인 전에는 아무것도 만들지 않는다**
- 세종예고2 사례(`교재구성.md` 2~5장)는 "참고: 세종예고2는 이렇게 했다"로만 덧붙인다

### 1-2. 단어장은 샘플 한 부를 먼저 만들어 승인받는다

## 2. 제작 (승인 뒤)

- **빌드는 공용 빌더 `공용/build/교재/` 로 한다 — 스크립트를 복사하지 않고 그 반 작업 폴더에 `교재.json` 만 쓴다** (`py ../공용/build/교재/build.py <교재.json> [--skip-prep]`, 형식은 `공용/build/교재/README.md`)
  - `교재.json` — 표지 · 원본 파일 · 단계(항목 · 쪽 · 숙제로 나눌 구간) · 정답(가져온 정답 쪽에서 남길 활동) · 수업계획 숙제 표 · 앞뒤로 돌릴 명령. 표지 · 차례 · 속표지 · 정답 통합 · 범위 밖 부분 지우기 · 원래 쪽번호 가리기 · 교재 쪽번호 · 쪽번호표(`_parts/쪽.json`) → 수업계획 숙제 쪽 자동 반영은 빌더가 한다
  - 직접 출제는 `data/*.json` (빌더의 `render.py` 가 조판). 출제 규칙은 그 반 `출제지침.md` 에 **그 반 출제경향으로 새로 쓴다** — 형식은 `공용/build/교재/README.md`
  - 빌더가 모르는 원본 정답 형식(다른 출판사)이 나오면 `원본정답.py` 에 종류를 하나 더한다. 그 반 내용 생성 스크립트(단어장 · 지문 정리 같은 것)는 반 작업 폴더에 두고 `prep` 에서 부른다
- 직접 출제가 많으면 출제를 나눠 맡기고(`Agent`), 그동안 빌드를 짠다
- 원본 쪽에 범위 밖 내용이 섞이면 그 부분을 **글자까지** 지운다(흰 칸만 덮지 않는다)

## 3. 품질 규칙 — 전 반 (`교재구성.md` 6-1)

- **검증**: 직접 출제한 묶음은 `검증` 에이전트에게 학생 시점에서 전부 풀게 한다 — 정답 · 복수 정답 · 원문 대조 · 강사 말투 · 범위 밖 낱말. 고친 뒤 바뀐 문항만 다시 검증, 많이 고쳤으면 그 회 전체
- **정답 누출**: 같은 쪽 · 같은 회 안에서 다른 문항의 답이 보이면 안 된다 — 예문 · 보기 · 밑줄 없는 원문 · **안내문 예시**까지
- **지문은 단 · 쪽 경계에서 자르지 않는다**
- **단어시험은 학생에게 미리 준 목록에서만** — 교재에 새 낱말 묶음을 넣고 시험에 쓰려면 목록을 먼저 나눠 준다
- **필요 없는 안내를 넣지 않는다** — 범위 밖을 뺐다는 말 · 쪽번호 위치 · 기호 설명
- 제목 · 선택지 꼴은 **그 학교 기출 형식**을 따른다 (출제경향에서 확인 — 세종예고 꼴을 옮기지 않는다)
- 학생 자료 규칙(루트 `CLAUDE.md`): 강사 말투 · 출제자 시각 · 배점 금지, 제목에 반 · 연도 · 무엇, 쪽번호. 교재에는 첫 쪽 삼각형 표식을 찍지 않는다 (10/15 강사 지시)
- 다 만든 뒤 `자체점검` 스킬

## 4. 마무리

- 쪽 배치를 바꿀 때마다 수업계획 · 계획표의 숙제 쪽이 따라 바뀌는지 확인한다 (쪽번호표로 자동 — 손으로 옮기지 않는다)
- 차례 · 속표지가 한 쪽에 들어가는지, 넘치면 빌드가 멈추게 한다
- 반 `CLAUDE.md` 「자료 위치」에 교재 · 빌드 경로를 적는다
- 그 반에서 강사가 새로 정한 것은 **그 반 `교재구성_제안.md`(결정 기록)** 에 적는다. 다른 반에도 쓸 품질 규칙이 새로 나오면 `교재구성.md` 6-1 에 한 줄 더하고 `공용/규칙/README.md` 변경기록에 남긴다
- 완성본은 브라우저 패널에 띄우고 파일 카드로 보낸다

## 하지 말 것

- 다른 반 교재 구성(단계 · 넣은 자료 · 쪽수 · 묶는 순서)을 그대로 옮기지 않는다 — 사례로만 보여 준다
- 승인 없이 만들지 않는다. 단어장 샘플 승인 전에 단어장 전체를 만들지 않는다
- 범위 밖 지문 · 수업에서 안 쓴 자료를 "많을수록 좋다"고 넣지 않는다
- 교재 쪽번호를 수업계획에 손으로 옮겨 적지 않는다
