# 단어 시험지

**공용 빌더로 만든다 — 스크립트를 새로 짜지 않고 data.json 만 쓴다.**

```
node 공용/build/단어시험지/build.js 단어시험/작업/<시험이름>/data.json --out 단어시험/배부
```
위 명령은 학원 폴더 기준이다. **반 폴더에서 연 세션이면 `node ../공용/build/단어시험지/build.js 단어시험/작업/<시험이름>/data.json --out 단어시험/배부`.**
파트 유형 10종·필드·자동 점검은 `공용/build/단어시험지/README.md`.
빌더가 DOCX → LibreOffice → PDF 로 만들고, 점검에 걸리면 PDF를 내보내지 않는다.
**빌더에 없는 파트 유형이 필요하면** 그 유형을 `build.js` 의 `TYPES` 에 추가한다 (반 폴더에 별도 스크립트를 만들지 않는다).

작업 위치는 해당 반의 `단어시험/작업/<시험이름>/`, 산출물은 `단어시험/배부/`.
**이 PC(맑은 고딕)는 옛 Cowork 판형보다 글자가 넓다** — `max_pages` 를 주고, 넘치면 파트의 `m`·`gap` 을 줄인다.

## 반별 골격 — 반 `CLAUDE.md` 「단어시험」이 정한다

교과서 단원 시험의 파트 구성(뜻쓰기 · 유의어 · 반의어 · 다의어 · 영영풀이 · 숙어 · 문맥 판단 등)과 문항 수는 반마다 다르다. **그 반 `CLAUDE.md` 「단어시험」 칸을 따른다.**
칸이 비어 있으면 지난 단어 시험지(`학교자료/`) · 주간보고서에서 확인하고, 그래도 없으면 첫 시험을 만들기 전에 선생님께 묻고 그 칸에 적는다.
그 학교 기출에 안 나오는 유형(예: 영영풀이를 안 내는 학교)은 넣지 않는다. 학교 규격 파일 `공용/build/학교/<학교>.json` 의 `vocab_test` 에 적어 두면 빌더가 막는다.
**이 골격은 교과서 단원 시험용이다.** 모의고사 · 외부지문 단어시험은 골격을 따르지 않는다 — 아래 절대 규칙 7번.

사례(이 템플릿을 만든 학원): 뜻쓰기 30 + 문장 속 대체어 5지선다 10 + 있는 대로 고르기 8 + 다의어 12 = 60문항 / 뜻쓰기 + 문장 빈칸(보기 선택) = 40문항.

## 절대 규칙 6개

1. **학교·반·번호 칸 금지.** 이름·점수만.
2. **재시험 기준·커트라인 문구 금지.**
3. **진도 안 나간 구간 출제 금지.** 본문 외 지문(FURTHER READING), 대화문(별도 지시 없으면). 반 `CLAUDE.md` 「시험 범위」에서 뺀 구간도 넣지 않는다.
4. **정답이 다른 파트에 노출되는 배치 금지.** 앞에서 뜻을 쓴 단어가 뒤 객관식 정답이면 안 된다.
5. **제시 방향은 영어 → 우리말.** 반 `CLAUDE.md` 「단어시험」에 예외가 적혀 있으면 그것만 따른다.
6. **학교 분석 시 다른 학교와 비교 금지.**
7. **학생이 공부한 단어장에 없는 유형은 내지 않는다.** 모고 단어장처럼 단어·뜻만 있으면 뜻쓰기로만 낸다. 유의어·반의어·다의어를 다른 교재(쏠북 등)에서 끌어와 채우지 않는다. 같은 반의 이전 모고 단어시험 형식을 먼저 확인하고 따른다. (40문항 가운데 16문항을 공부 범위 밖 유형으로 냈다가 다시 만든 적이 있다)

## 지면 규격

| 항목 | 값 |
|---|---|
| 용지 | A4 `{width:11906, height:16838}` dxa |
| 여백 | top 800~820 / right 900 / bottom 620~650 / left 900 dxa |
| 본문 폭 | `CONTENT = 10106` dxa |
| 글꼴 | 맑은 고딕 (컨테이너는 Noto Sans CJK KR로 대체) |
| 크기 | 제목 27~29 / 파트 헤더 19~20 / 본문 18 / 정답 15~16 / 주석 14~15 (half-point) |
| 강조색 | 남색 `1F4E79` (고등) · 주황 `C55A11` (중3) · 정답 빨강 `C00000` |

머리말 2행:
```
1행(회색 소자)  고2 영어 · YBM(박준언) 영어Ⅱ 2과 《The Subscription Economy》 · READING 본문 + CONVERSATION 대화문
2행(굵게+실선)  2026.09.15  양지고 2학년  영어Ⅱ 2과 단어시험   [ B형 ]
```
1행에 **출제 범위 구간을 반드시 명시한다.** 학생이 어디까지 외워야 하는지 알아야 한다.

이름·점수 칸:
```
이름 ______________________                              점수            /  60
```
좌측 이름, 우측 정렬 점수. 만점 = 문항 수.

답칸은 **셀 하단 테두리**로 만든다. 공백 문자에 underline을 걸면 LibreOffice에서 사라진다.
밑줄 길이는 **전부 동일**하게. 단어 길이에 맞추면 글자 수가 힌트가 된다.

## 단어 선정

1. **범위 필터가 1순위.** 교재 WORD TEST의 「교과서 어휘 목록」을 구간별로 갈라 쓴다(본문 / 대화문 / 본문 외 지문).
2. **진도 안 나간 구간은 스크립트가 거부한다.** 걸리면 빌드 실패.
3. **쉬운 단어는 뺀다.** 중3 기준 win/main/add/dream/believe/pay 등은 보기 오답으로만 재활용.
4. **개수는 총 문항 수에서 역산.** 지문이 여럿이면 지문별로 고르게 나눈다.

순서는 **무작위 재배치**. 교재 순서를 따라가면 순서로 외운 학생이 유리해진다.
`AORD` 배열로 좌·우 열을 교차시키고, 교재 순서와 연속 3개 이상 일치하면 빌드 실패시킨다.

## A형·B형

같은 범위로 두 벌을 만들 때는 셋 중 하나를 쓴다.

| 방식 | 언제 |
|---|---|
| **남은 단어를 B형 주력으로** | 표제어가 넉넉할 때. 모자란 만큼만 A형에서 끌어오되 **유형을 바꾼다** |
| **완전 분할** | 항목이 딱 떨어질 때 (영영풀이 26개 → 13/13) |
| **같은 단어, 다른 번호·다른 예문** | 풀이 고갈됐을 때. 순서 전면 재배치 + 예문 전량 교체 |

공통으로, **같은 번호에 같은 문항이 오면 빌드 실패**시킨다.

## 정답지

**별도 파일** `*_ANSWER.pdf`. 시험지와 **완전히 같은 배치에 답만 빨간색**으로 채운다.
표 칸 위치·문항 번호·줄바꿈까지 동일해야 두 장을 나란히 놓고 대조 채점할 수 있다.

배점 표기는 없다. 만점 = 문항 수, 1문항 1점.
부분점수·오탈자 기준은 아직 정해지지 않았다. **임의로 만들지 말고 물어본다.**

## 학생이 자주 틀리는 것 — 의도적으로 넣는 함정

| 처리 | 예 |
|---|---|
| 문맥 힌트 부착 | 뜻이 갈리는 단어에 교재 예문 구절을 회색 소자로. `set → within the set time`, `charge → charged an extra fee` |
| 철자 혼동 | `complement / compliment / complete / compete` 를 한 문항 선택지에 |
| in- 부정 착각 | `invaluable`(매우 귀중한) vs `valueless`(가치 없는) |
| 유의어를 반의어 문항 오답으로 | `diversity` 반의어를 묻는데 보기에 유의어 `variety` |
| 명사·동사형 구분 | `enrollment` 정답, 보기에 `enroll` |

오답 보기를 기초 어휘로만 채우지 않는다. 3~4문항 만에 소거법이 통한다 — **상대 세트 단어를 섞는다.**
숙어 파트에 예문 힌트를 주지 않는다. `add up` 에 "Small expenses can add up"을 주면 답이 그냥 보인다.

## 빌드 파이프라인

```
1. 원본 어휘 확인     반 학교자료/_텍스트/ 의 텍스트 변환본부터 (없으면 PDF)
   (아이콘·색 구분이 필요하면)  PDF 쪽을 PNG로 렌더 → Read로 이미지 확인
2. 범위 구간 분리     본문 / 대화문 / 본문 외 지문 — 진도 안 나간 구간은 data.json 에 넣지 않는다
3. data.json 작성    반 `CLAUDE.md` 「단어시험」 골격대로 parts · 유의어·반의어를 내면 lexicon 에 교재 단어장 값
4. 빌더 실행          node 공용/build/단어시험지/build.js <data.json> --out <배부>   ← 결함이 있으면 PDF 안 나옴
5. 렌더 확인          PDF 첫 쪽을 PNG로 → Read로 눈으로 확인
6. 전달
```
**범위 이탈 점검은 빌더가 교재 목록을 모른다** — 2단계에서 구간을 가르는 것이 범위 점검이다. 교재 목록 대조가 필요하면 data.json 의 lexicon 에 범위 안 단어만 넣는다.

## 빌드 스크립트에 넣을 검증

하나라도 걸리면 `throw`. PDF가 안 나온다.

- 총 문항 수 / 문항 번호 연속성
- 표제어 중복 (파트 내 · 파트 간)
- 뜻풀이 누락
- **출제 범위 이탈** — 본문 외 지문·대화문·교재 목록 밖
- 정답이 보기 안에 있는지 / 복수정답 누락은 없는지
- **정답이 다른 파트에 노출되는지**
- 우리말 뜻이 완전히 같은 항목
- 정답 번호 편중 / 순차 증가 / 연속 동일 / 유형별 위치 고정
- 유의어·반의어 정답이 **교재 단어장과 일치하는지**
- B형일 때 A형과 같은 번호·같은 유형인지
- 교재 순서를 연속 3개 이상 따라가는지

## 알려진 오류와 해결

| 오류 | 해결 |
|---|---|
| 밑줄이 렌더링 안 됨 | 공백에 underline → **셀 하단 테두리**로 |
| 밑줄이 문항보다 한 줄 아래 | 셀 테두리는 행 하단에 그려진다 → 같은 행 모든 셀에 bottom margin 소량 |
| 힌트 행에서 번호가 아래로 밀림 | `C_()` 헬퍼의 `verticalAlign` 하드코딩 → `o.va || VerticalAlign.BOTTOM` |
| 범위 검증이 `boast about ~` 에서 실패 | `norm()` 으로 `~`·`…` 제거 후 비교, 구(句)는 접두 일치 허용 |
| `pdftotext` 가 ⊜/⊖ 아이콘을 날림 | 유의어·반의어가 색·아이콘 구분이라 텍스트로 못 읽는다 → `pdftoppm` + 이미지 Read |
| 한글 폰트 깨짐 | `~/.config/fontconfig/fonts.conf` 에 맑은 고딕 → Noto Sans CJK KR 별칭 |
| 3페이지로 넘침 | 셀 `margins.top`·파트 `spacing.before` 를 twips로 조절, 렌더 확인 반복 |

## 미해결 — 손대기 전에 확인할 것

- 부분점수 · 오탈자 채점 기준은 반마다 다르다. 반 `CLAUDE.md` 「단어시험」에 없으면 묻는다.
