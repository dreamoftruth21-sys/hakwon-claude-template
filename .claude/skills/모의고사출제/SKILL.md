# 실전 모의고사 출제

빌더 형식은 `공용/build/모의고사/README.md`. 스크립트를 새로 짜지 않는다 — **data.json 하나만** 만들고 빌더를 돌린다.
형식 예시: `공용/build/모의고사/예시/샘플_3문항.json`.

## 한도 아끼기
시험지 한 회가 세션 문맥을 가장 많이 쓰는 일이다. 메인 세션은 배정표 · 빌드 결과 · 검증 결과만 들고 있는다.
- **한 번에 한 회차.** 여러 회를 한꺼번에 받으면 회차마다 에이전트 하나(`model: sonnet`)에 맡긴다
- 원문은 통째로 읽지 않는다 — 범위 지문은 `원본찾기` 에이전트로 찾아 그 대목만 받는다
- 스캔본(글자가 없는 PDF)은 처음 한 번만 이미지로 읽고 `학교자료/_텍스트/<같은 경로>/<파일명>.pdf.md` 로 옮겨 적는다. 다음 회차는 그 md 를 쓴다
- 기출은 다시 열지 않는다 — `분석/출제경향.md` 의 출제 공식만 본다
- data.json 은 지문 묶음별로 에이전트에 맡기는 것이 기본이다 (2절 끝)
- 고칠 때 data.json 전체를 다시 읽지 않고 그 문항만 고친다. 빌드 출력은 결함 줄만 본다

## 0. 조건 확인 (없으면 만들지 않고 말한다)
- 반 `분석/출제경향.md` — 없으면 `시험지분석` 스킬부터
- `공용/build/학교/<학교>.json` — 문항 수 · 배점표 · 서답형 · 안 내는 발문. 없으면 출제경향으로 만든다
- 반 `CLAUDE.md` 「시험 범위」 — 범위가 미정이면 묻는다. **진도가 안 나간 구간은 내지 않는다**
- 범위 원문 텍스트 — `학교자료/_텍스트/` (교과서 본문 · 학평 · 프린트). 원문 없이 지문을 지어내지 않는다

## 1. 제안 → 승인 (만들기 전에 멈춘다)
- **배정표**: 번호마다 지문 · 유형 · 배점. 실제 기출의 번호별 유형 순서를 따른다. 범위 지문은 한 회에 한 번씩 고르게
- **지난 회차와 겹침 피하기**: 같은 반 이전 회차 data.json 에서 문항별 지문 · 유형만 뽑아 보고(통째로 읽지 않는다) 같은 지문 × 같은 유형 조합을 다시 쓰지 않는다
- 난이도 · 특별히 넣을 함정(출제경향의 「출제 공식」)을 한 줄씩
- 사용자가 승인하면 2로

## 2. data.json 쓰기
위치: `<반>/시험대비/<시험>/작업/실전모의고사_<N>회/data.json`
- `name` 은 `<반>_<범위>_실전모의고사_<N>회` · `title` · `subtitle` · `footer` 에 반 · 연도 · 회차
- 지문 `kind`: 원문 그대로 `orig` / 문항용으로 고친 것 `edit`(+`restore` · `free`) / 새로 쓴 것 `rewrite`. **학교가 원문을 고쳐 내는 학교면 그 방식대로** (출제경향)
- `sources` 에 원문 경로를 적어 원문 대조를 켠다. `range_block` 에 범위 밖 소재 낱말
- `target` — 정답 위치를 고르게 (한 번호 몰림 · 3연속 금지는 빌더가 막는다)
- 해설 `sol` 은 정답 근거를 지문 구절로. 선택지를 돌리는 문항의 해설에 ①~⑤ 를 쓰지 않는다
- 학교에 서답형이 있으면 `kind: short/essay` · `answer` · `criteria` · 단어 쓰기는 `accept`(인정 답 목록 — 온라인 자동 채점용)
- 회차마다 심은 장치는 `checks` 로 확인 (README 표)
지문 묶음별로 나눠 에이전트(`model: sonnet`)에 맡기는 것이 기본이다 — 이 절과 그 묶음의 배정표, 출제경향의 출제 공식, 원문 경로를 넘기고 문항 조각만 돌려받아 합친다. 열 문항 미만이면 메인 세션이 직접 써도 된다.

## 3. 빌드 → 결함 0
```
py 공용/build/모의고사/build.py <data.json> --out <반>/시험대비/<시험>/배부
```
결함이 나오면 data.json 을 고치고 다시. **결함 0이 아니면 PDF 가 나오지 않는다.** 우회하지 않는다.

## 4. 검증 (건너뛰지 않는다)
- `검증` 에이전트에 학생용 PDF · 답지 PDF · 원문 위치를 넘긴다 — **학생용만 먼저 보고 전 문항을 직접 푼 뒤** 답지와 맞춘다
- 지적(복수정답 · 근거가 지문 밖 · 문항 사이 정답 누출 · 원문에 없는 문장)을 고치고 다시 빌드 → 고친 문항만 다시 검증
- 빌더가 결함 0이어도 검증에서 복수정답이 나온 적이 있다

## 5. 전달
- 시험지 · 답지 PDF 를 브라우저 패널에 띄우고 파일 카드로 보낸다
- 보고: 문항 수 · 배정표 요약 · 결함 0 · 검증에서 고친 것
- 온라인으로 풀게 할지 묻는다 → `온라인배포` 스킬
- 오늘 수업에 쓰면 그날 수업 폴더에 번호를 붙여 복사한다 (`3_수업_…` · 숙제면 `4_내줄숙제_…`)

## 수학이면
순서(0 → 5)는 같고 빌더 · 데이터만 다르다. 형식은 `공용/build/수학/README.md`, 예시는 `공용/build/수학/예시/샘플_수학.json`.
- 0: 학교 규격은 `<학교>.json` 의 `math_exam`. 범위는 단원 이름으로 `covered` 에 적는다 (진도 밖 단원 문항은 빌더가 멈춘다). 지문 원문 대신 교과서 · 부교재 문항 구조를 본다
- 1: 배정표는 번호마다 단원 · 유형 · 배점 · 그림 여부. 지난 회차와 같은 단원 × 유형 × 같은 수치를 다시 쓰지 않는다
- 2: 위치는 같다(`작업/실전모의고사_<N>회/data.json`). `"subject": "math"`. 수식은 `$…$` 이고 **JSON 안의 역슬래시는 두 번**(`\\dfrac`)
  - 계산이 있는 문항은 모두 `verify`(sympy) — 선택형은 정답이 하나뿐인지, 단답 · 서술형은 모범답안 값이 맞는지 빌더가 계산해 본다
  - 오답 선택지는 출제경향의 「흔한 실수의 값」으로 짓는다. 값이 같은 선택지(√8 과 2√2)는 빌더가 막는다
  - 그림은 좌표 · 작도 도우미로 정의하고(README 「그림(fig)」) `asserts` 로 문제 조건(길이 · 각)을 확인한다. 짐작한 좌표를 쓰지 않는다
  - 서술형은 `steps`(채점 단계 · 부분 점수, 합이 배점) · `criteria`. 숫자가 아닌 단답을 온라인으로 자동 채점하려면 `accept`
  - 선택지는 돌리지 않는다 — 정답 위치는 `ans`(0부터)로 직접 고르게 둔다
- 3: `py 공용/build/수학/build.py <data.json> --out <반>/시험대비/<시험>/배부`
- 4: 검증은 영어와 같이 건너뛰지 않는다 — `검증` 에이전트가 학생용 PDF 만 보고 전 문항을 풀고 답을 적은 뒤 답지와 맞춘다 (`자체점검` 스킬 「수학 시험지」). verify 는 출제자가 쓴 식이 맞다는 전제라 문제 자체의 오류(조건 부족 · 답 없음)는 못 잡는다

## 하지 말 것
- 그 학교 기출에 없는 발문 · 유형 · 선택지 언어를 쓰지 않는다 (학교 json 이 막는 것도 있다)
- 범위 밖 지문 · 진도 안 나간 부분을 넣지 않는다
- 검증 없이 배부하지 않는다
