# 수업 계획표

계획표의 쓸모는 **진도 확인**이다 — 지금 어디까지 했고 시험까지 얼마나 남았는지. 회차마다 진도 한 줄만 적는다.
쪽 번호 · 숙제 · 자료명은 상황에 따라 계속 바뀌므로 넣지 않는다. 그건 그날 `수업안.md` · `수업일지.md` 에 쓴다.

반 폴더 세션에서 쓴다. 반 폴더가 아니면 어느 반인지 먼저 묻는다.
빌더와 json 형식은 `공용/build/수업계획/README.md` (반 폴더에서는 `../공용/…`).

| 하는 일 | 언제 |
|---|---|
| A. 새로 짜기 | 시험 범위가 나오거나 대비 기간을 시작할 때 |
| B. 끝난 회차 표시 | 수업을 마칠 때마다 — `수업준비` 스킬 9단계가 부른다 |
| C. 일정 고치기 | 진도가 밀리거나 휴강이 생기거나 시험 날짜가 바뀔 때 |

## A. 새로 짜기

### 1. 읽는다
- 이 반 `CLAUDE.md` (자동으로 올라와 있다) — 시험 날짜 · 범위 · 수업 요일 · 반 규칙
- 루트 `CLAUDE.md` 의 공통 휴강 · 공휴일
- `분석/출제경향.md` 의 최신 장 — 범위 구성과 유형 비중만
- `수업일지.md` 의 **지난 대비 기간** — 한 회에 얼마나 나갔는지만 본다. 처음부터 다 읽지 않는다
- `학생.md`
- 이 시험의 계획 문서가 이미 있으면 (`분석/…수업계획.md` · 옛 상세 계획 HTML) 거기 적힌 결정을 따른다. 결정을 새로 내리지 않는다

### 2. 수업일을 센다
시작일부터 시험 전날까지 이 반 요일을 세고 휴강 · 공휴일을 뺀다. 날짜가 미정이면 가정한 날짜를 쓰고 `시험_메모` 와 `확인` 에 적는다.

### 3. 제안하고 멈춘다
만들기 전에 채팅으로 이만큼만 내놓고 승인을 기다린다.

```
수업 N회 (M/D ~ M/D, 요일) · 시험 M/D (가정이면 가정)

구간
- ① 이름 — K회 (M/D ~ M/D) · 무엇을 어떤 순서로
- ② …

매 수업: (고정 순서 · 반마다 고정 활동)
확인 필요: (미정 사항)
근거: (어느 기록에서 나온 판단인지 한 줄씩)
```

구간은 진도 덩어리다 (과 · 학평 · 문법 · 실전 · 마무리). 구간마다 회차 수를 먼저 정하고 날짜를 붙인다.
남은 회차로 못 끝낼 분량은 잡지 않는다. 모자라면 무엇을 줄일지 제안에 적는다.

### 4. 승인 뒤 만든다
1. `시험대비/<시험>/작업/수업계획/계획.json` 을 쓴다 — `공용/build/수업계획/예시/` 를 본뜬다
   - `파일` = `<반>_<학기><시험>_수업계획` (예 `중앙고2_2학기기말_수업계획`)
   - `진도` 는 한 줄. 무엇을 어디까지 (`3과 본문 해석 · T/F` · `2026 10월 31~33번` · `실전 2회`)
   - 반마다 매 수업 고정으로 하는 활동(매 수업 영작 2문장 등)과 학생별 추가 과제는 칸마다 쓰지 않고 `매수업` 에 한 번 쓴다. 날짜가 정해진 것만 그 회차 `메모` 에 쓴다
   - 학생 진단 · 중간 결과 분석처럼 긴 근거는 `분석/` md 에 두고 `상세` 에 경로만 쓴다
2. 빌드한다: `py ../공용/build/수업계획/build.py 시험대비/<시험>/작업/수업계획/계획.json`
3. 결함이 나오면 json 을 고쳐 다시 돌린다. 경고(1쪽 넘음 · 진도가 김)도 고친다
4. `자체점검` 스킬로 점검한다 — 날짜 · 요일 · 휴강이 반 `CLAUDE.md` 와 맞는지, 범위 밖 진도가 없는지
5. 반 `CLAUDE.md` 의 계획 경로 줄을 새 파일로 바꾼다 (`계획표: <파일>.html · 데이터 시험대비/<시험>/작업/수업계획/계획.json`)
6. 같은 시험의 옛 계획 파일이 반 폴더 최상위에 있으면 지우지 않는다. `분석/` 로 옮겨 상세 근거로 남길지 사용자에게 묻는다. 옛 문서에 일정 표가 따로 있으면 둘이 어긋날 수 있다고 알린다
7. PDF를 브라우저 패널에 띄우고 파일 카드로 보낸다

## B. 끝난 회차 표시

수업일지에 기록된 회차에 `"끝": true` 를 넣고 다시 빌드한다. **기록이 없는 회차는 끝으로 표시하지 않는다.**
- 실제로 나간 진도가 계획과 다르면 그 회차 `진도` 를 실제대로 고치고 `메모` 에 원래 계획을 적는다 (`메모: "계획은 본문 2/4 — 중간고사 정리로 하루 밀림"`)
- 한 회차가 밀렸으면 뒤 회차를 어떻게 할지는 C 로 넘긴다. 혼자 뒤를 당기거나 줄이지 않는다
- 빌드 출력의 `기록?` 경고(지난 날인데 끝 표시가 없음)는 일지를 확인해 끝을 넣거나 C 로 넘긴다

## C. 일정 고치기

밀린 회차 · 새 휴강 · 확정된 시험 날짜를 반영해 남은 회차를 다시 배치한다.
1. 남은 회차 수와 남은 진도를 비교한다
2. 줄일 것 · 합칠 것 · 뒤로 미룰 것을 채팅으로 제안하고 승인을 받는다 (A-3 형식으로 바뀐 구간만)
3. json 을 고치고 다시 빌드한다. 끝난 회차는 건드리지 않는다

## 하지 말 것
- 회차 칸에 쪽 번호 · 숙제 · 자료 파일명을 쓰지 않는다
- 수업일지에 없는 회차를 끝으로 표시하지 않는다
- 승인 없이 남은 일정을 당기거나 줄이지 않는다
- 공휴일에 수업을 잡지 않는다 (빌더가 막는다)
- 다른 반 폴더를 읽지 않는다
