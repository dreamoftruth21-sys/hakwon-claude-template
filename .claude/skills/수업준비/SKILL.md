# 수업 준비

반 폴더 안에서 실행한다. 반 폴더가 아니면 **어느 반인지 먼저 묻는다.** 추측하지 않는다.

이 스킬은 **두 구간으로 나뉜다.**

| 구간 | 하는 일 | 끝나는 지점 |
|---|---|---|
| **1~5단계 · 조사** | 날짜·기록·D주차·숙제·진도를 파악한다 | **5-1 수업안 제안 → 멈춘다** |
| **6~9단계 · 제작** | 자료를 만들고 점검하고 일지를 채운다 | 승인이 떨어진 뒤에만 들어간다 |

**승인 없이 6단계로 넘어가지 않는다.** 시험지·워크북·PDF를 한 장도 만들지 않는다.
조사 도중 자료가 뻔히 없다는 게 보여도 만들지 말고 **5-1 제안에 "만들 자료"로 적어 올린다.**

한 번에 끝내려 하지 말 것. 제안에서 멈추는 것이 이 스킬의 정상 종료다.

## 순서

### 1. 오늘이 어느 반 수업인지 확인
`date` 로 오늘 날짜와 요일을 확인한다. 이 반 `CLAUDE.md` 의 요일과 대조한다.
루트 `CLAUDE.md` 의 전 반 공통 일정(휴강)도 확인한다.
오늘 수업이 없는 반이면 그 사실을 말하고, 다음 수업일을 기준으로 준비할지 묻는다.
반 `CLAUDE.md` 「반 편성」에 요일 · 타임마다 명단이 다르다고 적혀 있으면 **오늘이 어느 타임인지 반드시 구분한다.**

### 2. 지난 기록 읽기
- `수업일지.md` 최근 **3회분**만 읽는다. 더 읽지 않는다 — 컨텍스트가 커진다.
- `학생.md` 를 읽는다.
- 이 반 `CLAUDE.md` 는 자동으로 올라와 있다. 다시 읽지 않는다.

**수업일지가 비어 있거나 최근 회차가 빠져 있으면 메모와 출석부를 본다.**
반 `학교자료/주간보고서/` · `학교자료/출석부/` 의 텍스트 변환본(`학교자료/_텍스트/`)에 그날 진도 · 숙제 · 단어시험이 적혀 있다.
계획과 실시 기록이 어긋나면 **실시 기록이 맞다**.

여기서도 진도가 안 잡히면 **추정하지 말고 5-1 제안에 "확인 필요"로 올린다.**
진도를 잘못 잡으면 출제 범위가 이탈한다.

### 3. D-주차 계산
이 반 `CLAUDE.md` 맨 위의 시험 날짜에서 남은 일수를 구한다.

| 남은 기간 | 모드 | 쓰는 폴더 |
|---|---|---|
| 5주 초과 | 정규수업 | `정규수업/` |
| 5주 이내 | 시험대비 | `시험대비/<시험>/` |

주차별 우선순위가 다르다.
- **D-5** 범위 확정 · 단어 1회전 · 본문 1회독
- **D-4** 본문 정독 + 문법 포인트 · 단어 2회전
- **D-3** 변형문제 투입 시작 · 어법 점검지
- **D-2** 실전 세트 · 오답 정리 · 서답형 훈련
- **D-1** 최종 점검 · 예상문제 · 약한 데만 재훈련. **새 자료를 만들지 않는다.** 이미 푼 것에서 틀린 것만 다시 본다

### 4. 지난 숙제 확정
지난 회차 일지의 `숙제` 항목을 그대로 가져온다.
학생별로 **지난번에 안 해온 사람, 단어시험 Fail로 재시험 대상인 사람**을 뽑아 이름을 적는다.

#### 4-1. 온라인 제출 확인
지난 숙제 중에 온라인 답안지로 배포한 시험이 있으면 **학생이 낸 답을 먼저 확인한다.**
- 배포한 시험 ID는 `공용/온라인채점/README.md` 의 "링크" 절에서 이 반 이름으로 찾는다
- 결과는 구글 시트 `온라인채점` (드라이브 도구 `search_files` 로 title = '온라인채점' 을 찾는다) — Drive 도구 `download_file_content` 에 xlsx(`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`)로 받아 openpyxl 로 연다 (`read_file_content` 는 앞부분 표본만 줘서 최근 제출이 빠진다). `제출` 탭에서 이 반 시험 ID·학생 이름 줄만 보고, 틀린 서답형의 학생 답은 `문항별` 탭에서 본다
- **지난 수업 이후 제출된 것**만 새로 적는다. 이미 일지에 적힌 제출은 다시 적지 않는다
- 학생별로 시험 · 점수 · 틀린 번호를 적는다. 틀린 번호는 그 시험 `data*.json` 의 `questions` 에서 유형(어법·빈칸 등)을 찾아 붙인다 — 같은 유형이 몰리면 한 줄로 짚는다
- 같은 시험을 여러 번 냈으면(`시도` 2 이상) 첫 시도를 기준으로 적고 최고점을 괄호로 붙인다
- 배포했는데 **제출이 없는 시험**은 "미제출"로 적는다 — 종이로 풀었을 수 있으니 수업안에 "종이로 풀었으면 답지로 채점"을 붙인다
- 사용자가 테스트로 낸 기록이라고 한 것은 일지에 남아 있다. 일지를 보고 걸러낸다
- 확인한 결과는 5-1 제안의 "지난 숙제" 에 넣고, 승인 후 수업일지 뼈대의 `학생별:` 칸에 적는다
- 시트를 못 열면(연결 끊김 등) 그렇다고 적고 넘어간다. 추정으로 채우지 않는다

반 `CLAUDE.md` 에 다른 반 · 다른 선생님과 숙제를 맞추는 규칙이 있으면 그대로 따른다.

### 5. 오늘 진도 결정
지난 회차 `다음` 항목이 출발점이다. 없으면 일지에서 마지막으로 나간 데를 찾는다.
D-주차와 남은 회차 수를 따져 오늘 어디까지 나가야 하는지 판단한다. **못 끝낼 분량을 잡지 않는다.**
수업 계획표가 있으면(`시험대비/<시험>/작업/수업계획/계획.json`) 오늘 날짜의 회차 `진도` 와 대조한다. 어긋나면 5-1 제안에 "계획표: 오늘 회차는 ○○ — 실제는 △△"로 적는다.

### 5-1. 수업안을 제안하고 승인을 받는다 — 여기서 멈춘다

여기까지 정한 것을 짧게 내놓고 **사용자의 승인을 기다린다.**

```
오늘 이렇게 하면 될까요?

- 지난 숙제: (지난 수업에 낸 숙제 / 재시험 대상)  ← "걷을 것"이라고 쓰지 않는다 (2026-09-30 강사 지정)
- 온라인 제출: (학생 · 시험 · 점수 · 틀린 번호와 유형 / 미제출 시험. 배포한 게 없으면 이 줄을 뺀다)
- 진도: (어디부터 어디까지)
- 단어시험: (범위 · 문항 수 · 새로 만들지 기존 것을 쓸지)
- 만들 자료: (파일명과 구성. 없으면 "없음")
- 낼 숙제: (언제까지)
- 확인 필요: (기록이 없어 못 정한 것. 없으면 이 줄을 뺀다)
```

**근거를 한 줄씩 붙인다** — 어느 기록에서 나온 판단인지. "9/14 출석부", "지난 일지 다음 항목" 처럼.
근거가 없는 항목은 추정이다. 추정이라고 적는다.

승인 전에는 **자료를 만들지 않는다.** 시험지·워크북·PDF를 한 장도 내지 않는다.
사용자가 고치라고 하면 고쳐서 다시 제안한다. 승인이 떨어지면 6단계로 간다.

### 6. 단어 시험지 (승인 후)
이 반에 오늘 단어 시험이 있는지 판단한다 (`단어시험/배부/` 의 최근 파일과 일지를 본다).
필요하면 `단어시험지` 스킬을 쓴다. 범위는 오늘 진도 직전까지다 — **진도가 안 나간 구간은 절대 넣지 않는다.**
같은 범위로 이미 나간 시험지가 있으면 A/B형 규칙을 따른다.

### 7. 자료 만들기 (승인 후)
오늘 쓸 자료가 이미 있으면 경로를 적는다. 없으면 **만든다.**

**공용 빌더가 있는 종류는 스크립트를 새로 짜지 않고 data.json 만 만든다.** 형식은 각 README.
아래 경로는 학원 폴더 기준이다. **반 폴더에서 연 세션이면 앞에 `../` 를 붙인다** (`py ../공용/build/모의고사/build.py …`). data.json 안의 원본 경로는 어디서 실행하든 학원 폴더 기준이다.
| 자료 | 빌더 |
|---|---|
| 실전 모의고사 (학교 규격, 단답·서술형 포함) | `py 공용/build/모의고사/build.py <data.json>` |
| 단어장 (지문별 쪽 · 원본 쪽 끼우기 · 책 형태) | `py 공용/build/단어장/build.py <data.json>` |
| 학평 변형문제집 재조판 | `py 공용/build/변형문제/재조판.py <data.json>` |
| 내신기출·변형문제 지문 지우기·뽑기 | `py 공용/build/변형문제/기출가공.py <data.json>` |
| 단어 시험지 | `node 공용/build/단어시험지/build.js <data.json>` |
| 교재 쪽 뽑기 (수업·숙제·답지) | `py 공용/build/쪽뽑기/extract.py <교재키> <인쇄쪽> <저장경로>` — 교재가 `교재.json` 에 없으면 먼저 등록 |

data.json 은 반 `시험대비/<시험>/작업/<자료이름>/` (또는 `단어시험/작업/`) 에, PDF는 `--out` 으로 같은 구역 `배부/` 에 둔다.
빌더에 없는 형식이면 그 `작업/` 에서 새로 짜되 `공용/build/core` 를 가져다 쓴다.
만든 뒤에는 `자체점검` 스킬을 돌린다. 점검 없이 내놓지 않는다.

### 7-1. 그날 수업 폴더를 만든다 (승인 후)

반 폴더 안에 `<MMDD요일>/` (예: `0922월`) 을 만들고 **그날 여는 파일을 번호를 붙여 넣는다.** 수업 중에 이 폴더 하나만 열면 되게 한다.

| 번호 | 무엇 |
|---|---|
| `1_단어시험_…pdf` · `1_단어시험_…_답지.pdf` | 오늘 볼 단어 시험 |
| `2_숙제확인_…_답지.pdf` | 지난 수업에 낸 숙제의 답지 |
| `3_수업_….pdf` | 오늘 쓸 자료 |
| `4_내줄숙제_….pdf` | 오늘 내줄 숙제 — **파일 이름에 "내줄숙제"를 넣는다** (2026-10-14 지정, 전 반). 여러 개면 합본 `4_내줄숙제_합본_양면인쇄.pdf` (`숙제합본` 스킬). 답지는 다음 수업 폴더의 `2_` 로 |
| `수업안.md` | 오늘 순서 · 지난 숙제 · 낼 숙제 (5-1 제안을 그대로 저장) — `수업정리` 스킬이 이 파일을 읽는다 |

- 여러 수업에 걸쳐 쓰는 교재(통합워크북·단어장)는 **원본을 `시험대비/<시험>/배부` 에 두고**, 그날 필요한 답지만 이 폴더로 복사한다.
- 월수·화목처럼 같은 내용을 두 번 나가도 **날마다 폴더를 따로 만든다.** 복사본이 생겨도 괜찮다.
- 달이 바뀌면 지난달 수업 폴더는 반 폴더 안 `<YYYY-MM>/` 로 옮긴다 ("월말 정리"). 새 달 출석부를 받으면 `학교자료/출석부/` 에 넣고 지난달 것은 그 안 `<N월>/` 로 옮긴다.

### 8. 브리핑 출력 (승인 후)
아래 형식으로 짧게 낸다. 길게 쓰지 않는다.

```
## 2026-09-15 (화) · 중앙고2 · D-1주 (중앙고 9/22)

**지난 숙제**
- 지난 숙제: L6 본문 해석 1~20번
- 재시험: 학생G (09-11 단어시험 Fail)

**오늘**
- L6 Boggis 결말 파트 마무리 → 예상문제 세트 1회
- 단어시험: L5-6 통합 40문항 (신규 제작 완료)

**준비된 자료**
- 시험대비/2026-2학기-중간/배부/L5-6_예상문제_2회.pdf  ← 오늘 만듦
- 단어시험/배부/M3_L56_TEST_0915.pdf  ← 오늘 만듦

**낼 숙제**
- 예상문제 2회 오답 정리 + L5 어법괄호 10개 재점검 (금요일까지)

**챙길 것**
- D-1주다. 새 유형 투입 금지. 틀린 것만 다시
```

**파일 카드는 세 묶음으로 보낸다** (`SendUserFile`, 2026-10-14 지정 · 전 반).
1. **지난 숙제** — 지난 수업에 낸 숙제 파일 자체(지난 수업 폴더의 `4_내줄숙제_…` 또는 옛 이름 `4_숙제_…`, 합본이 있으면 합본) **와** 그 답지(`2_숙제확인_…`). 답지만 보내지 않는다 — 무엇을 냈는지 선생님이 바로 볼 수 있어야 한다
2. **오늘 진도** — 폴더의 `1_` · `3_` 파일 **전부** (단어시험 A형 · B형 재시험, 수업 자료, 화면용 자료, **각 답지까지**). 학생용만 골라 보내지 않는다
3. **오늘 내줄 숙제** — `4_내줄숙제_…` (합본이 있으면 합본)

### 9. 수업일지에 뼈대 추가 (승인 후)
`수업일지.md` 맨 위에 오늘 항목을 만들어 둔다. 점수와 학생별 기록은 **비워 둔다** — 수업 후에 채운다.

```markdown
## 2026-09-15 (화) · 중앙고2 · D-1주
- 진도:
- 숙제:
- 단어시험:
- 학생별:
- 특이:
- 다음:
```

### 9-1. 계획표에 끝난 회차 표시 (승인 후)
수업 계획표가 있으면 `수업계획` 스킬 B 로 **일지에 기록된 지난 회차**에 끝 표시를 하고 다시 빌드한다. 오늘 회차는 표시하지 않는다 — 수업이 끝나야 끝이다.
계획과 다르게 나간 회차나 밀린 일정은 브리핑 "챙길 것"에 한 줄로 적고, 남은 일정을 고칠지는 사용자에게 묻는다.
