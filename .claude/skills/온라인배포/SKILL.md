# 온라인 답안지 배포

구조와 설치는 `공용/온라인채점/README.md`. 웹앱은 이미 배포되어 있다 — **새 시험은 채점키 json 하나만 만들면 된다.** 재배포하지 않는다.

## 1. 어떤 자료인지 정한다

- 사용자가 말한 자료, 없으면 오늘 수업 폴더(`<MMDD요일>/`)에 있는 시험지
- 그 자료의 `시험대비/<시험>/작업/<자료>/data*.json` 을 찾는다 (한 폴더에 `data1.json`·`data2.json` 처럼 회차별로 있기도 하다 — `title` 로 맞는 것을 고른다). `questions` 가 있는 **공용 모의고사 빌더 형식**이어야 한다
- 이미 올린 시험을 다시 만들 때는 기존 채점키의 `data` 칸에 원본 경로가 적혀 있다
- **모의고사 형식이 아니어도 문항·정답·인정 답이 json 에 있으면 올릴 수 있다.** 그 자료 `작업/` 폴더에 채점키 변환 스크립트를 두고(`채점키.py` 의 `norm_text`·`students` 를 가져다 쓴다) 같은 모양의 채점키를 만든다. 예: 양지고2 서답형 집중 연습 — `양지고2/시험대비/2026-2학기-중간/작업/서답형연습/채점키_만들기.py` (빈칸 1개 1점, 칸별 자동 채점). 이 경우 답지 PDF 대조가 없으니 모범답안을 넣어 만점이 나오는지 직접 확인한다
- 문항·정답이 json 으로 없으면(옛 스크립트·변형문제 재조판 등) 만들지 말고 "이 자료는 아직 온라인 채점이 안 된다"고 말한다
- 후보가 여럿이면 묻는다

## 2. 시험 ID

`<반>_<짧은 자료명>` — 예: `세종예고1_실전1회`, `한솔고2_실전2회`. 한글·영문·숫자·`_`·`-` 만.
`공용/온라인채점/채점키/` 에 같은 ID가 있으면 **덮어쓰기 전에 묻는다** (학생이 이미 푼 시험일 수 있다).

## 3. 채점키 생성

```
py 공용/온라인채점/채점키.py <data.json> --id <ID> --open
```
(반 폴더 세션이면 `py ../공용/온라인채점/채점키.py …`)

- `--open` 은 항상 붙인다 — 결과 화면에 틀린 번호가 보인다 (2026-09-23 사용자 결정)
- **한솔고는 `--models` 도 붙인다** — 제출 뒤 서답형마다 내 답과 모범답안을 보여 준다 (2026-09-28 사용자 결정)
- **답지 PDF와 정답이 하나라도 다르면 스크립트가 멈춘다.** 우회하지 말고 어느 문항이 다른지 사용자에게 보고한다
- 답지 PDF를 못 찾으면 멈춘다. 파일명이 `<data.json 의 name>_답지.pdf` 인지 확인하고 사용자에게 묻는다
- 서답형도 들어간다. 기호 고르기 단답은 자동 채점. **단어 쓰기 단답은 data.json 에 `accept`(인정 답 목록)를 넣으면 자동 채점된다** — 양지고는 넣는다 (2026-09-29 사용자 결정). `accept` 는 `criteria` 의 인정 답과 같게 쓴다(형식은 README). 서술형·accept 없는 단어 쓰기는 입력만 받는다. 보고에 "자동 채점 N점 · 선생님 채점 M점"을 적는다
  - (1)~(3) 칸이 있는 문항은 `accept` 를 칸별 목록으로, 칸별 배점은 `accept_pts` 로 준다 → 학생 화면에 칸이 나뉘어 나오고 칸마다 부분 점수
  - 비교는 대소문자·앞뒤 공백·끝 마침표·굽은 따옴표만 무시한다. 철자는 그대로 본다. **목록에 없는 답은 0점** — 채점기준의 "뜻이 통하는 ~ 인정" 같은 열린 기준은 흔한 답을 목록에 펼쳐 넣는다
  - 줄임말은 1단어로 센다 (양지고 — 2026-09-29 선생님 결정)
- `쪽:` 줄이 `없음` 이거나 `못 찾음` 이 나오면 쪽 경계 굵은 줄이 빠진다. 보고에 적는다
- `유형 미분류 → 기타` 가 나오면 보고에 적는다 (채점에는 지장 없다)
- 학생 명단은 `<반>/학생.md` 의 `- **이름**` 줄이다. 명단이 틀리면 학생.md 를 먼저 고친다

## 4. 해설 쓰기 (결과 화면 [해설 보기] — 2026-09-30 사용자 결정)

```
py 공용/온라인채점/해설재료.py <ID> --out <스크래치패드>/<ID>.md
```
재료(지문·발문·**인쇄된 순서의 선택지**·✔정답·원본 해설)를 끝까지 읽고 `공용/온라인채점/해설/<ID>_해설.json` 을 쓴 뒤
```
py 공용/온라인채점/해설넣기.py <ID>
```
점검 통과까지 고친다. 문항이 많으면(26문항 × 여러 회차) 시험별로 에이전트에 나눠 맡겨도 된다 — 이 절을 그대로 넘긴다.

형식: `{"3": {"exp": "..."}, "7": {"exp": "...", "why": {"1": "...", "2": "...", "4": "...", "5": "..."}}}` — 키는 재료의 `[번호]` (서답형은 "서답형 2")

- **모든 문항**에 exp — 두세 줄, 170자 이하. 맞은 학생도 본다
- **why 는 어법·어휘 선택형에만**, 정답을 뺀 선택지 번호 전부 (90자 이하). 그 선택지가 왜 맞는 표현인지(=왜 답이 아닌지). 학생 화면에는 그 학생이 고른 번호 것만 나온다
- 학생이 읽는 글: "~다" 평서체. 하세요·판서·채점하면·학생이·출제자·배점 금지, **점수 이야기(N점·부분 점수·감점·"~만 인정") 금지**. 원본 해설·지문에 있는 것만 쓴다

| 유형 | 틀 |
|---|---|
| 어법 | 틀린 곳 → 고친 형태 · **문법 개념 용어**로 규칙 (예: "ⓓ draw → drawing · 앞의 taking과 and로 이어진 병렬 구조"). why: 그 밑줄이 맞는 까닭을 용어로 ("ⓑ discover — help + 목적어 + 동사원형(목적격 보어)") |
| 어휘 | 틀린 낱말 → 맞는 낱말 · 문맥 근거. why: 그 낱말이 문맥에 맞는 까닭 |
| 빈칸 | 정답 뜻 · 근거 본문 구절 하나 |
| 주제·제목·요지·목적 | 글의 요지 한 줄 · 흔한 오답이 틀린 까닭 한 줄 |
| 요약 | (A)·(B) 각각 근거 구절 |
| 내용 일치·불일치·이해·사례 | 본문 구절 ↔ 선택지 구절 대조 |
| 순서 / 삽입 / 무관한 문장 | 연결 고리 흐름 / 들어갈 곳과 앞뒤 단서 / 글 흐름과 벗어난 점 |
| 지칭 / 함축 의미 | 틀린 것의 실제 대상 / 밑줄 뜻풀이 |
| 기호 단답 | 빠뜨리거나 잘못 넣기 쉬운 기호마다 까닭 |
| 단어 쓰기(자동) | 칸마다 정답과 문법 근거 |
| 서술형·단어 쓰기(선생님 채점) | 모범답안은 화면에 따로 나오므로 되풀이하지 않고, 핵심 요소와 근거 본문 위치 |

채점키를 채점키.py 로 다시 만들면 해설 파일이 있을 때 자동으로 다시 들어간다. 다른 스크립트로 만든 채점키(약점확인·서답형연습 등)는 그 뒤에 해설넣기.py 를 다시 돌린다.

## 5. 링크 확인

링크 = README "링크" 절의 웹 앱 URL + `?t=<ID>`

- 브라우저 패널로 링크를 열어 **제목과 문항 수가 맞는지** 본다
- `시험을 찾지 못했다` 가 뜨면 드라이브 동기화가 아직이다. 1~2분 뒤 다시 연다. 계속 안 되면 사용자에게 json 파일을 내 드라이브에 직접 올려 달라고 한다
- **이름 `TEST` 로 한 번 제출해 본다** (2026-09-30 선생님 지시). TEST 는 서버가 모든 시험 명단 끝에 자동으로 붙인다 — 학생.md·채점키에 넣지 않는다. 몇 번이든 다시 낼 수 있고 알림 메일은 가지 않는다
  - 모든 문항을 채우고(정답 몇 개·오답 몇 개 섞어) 제출 → 점수·점수 아래 한마디·틀린 번호·"더 노력할 부분"(같은 유형을 2개 이상 틀리게 내면 나온다)·[해설 보기]·(어법·어휘) "내가 고른 ~" 줄이 나오는지 본다
  - 결과 화면이 구글 보안 틀(iframe) 안이라 스크립트로 못 누른다. 화면 좌표로 클릭한다. 이름 칸은 클릭 → Esc → ↓ 로 고른다 (TEST 는 맨 끝)
  - 학생 이름으로는 제출하지 않는다 — 한 번만 낼 수 있어 학생이 못 푼다

## 6. 보고

- 학생에게 보낼 링크 (코드 블록으로 — 그대로 복사해 카톡에 붙인다)
- 문항 수 · 자동 채점 점수 / 선생님 채점 점수 · 답지 대조 통과 · 쪽 경계 표시 여부 · 해설 점검 통과(선택지 이유 N문항)
- README "링크" 절에 한 줄 추가: `- <반> <자료>: <웹 앱 URL>?t=<ID>`

결과는 구글 시트 `온라인채점` 의 `제출`(학생별 점수·틀린 번호·채점 대기) · `문항별`(유형·출처·학생 답·정오·득점) 탭에 쌓인다.
- 자동 채점된 서답형의 `정오` 는 O(다 맞음) · △(일부만) · X(0점), `득점` 에 부분 점수가 들어간다
- `최종 점수` 는 `문항별` 득점 합계 수식이다 — 선생님 채점 서답형은 득점을 넣으면 확정되고, 목록에 없던 정답을 인정하려면 그 줄 득점만 고치면 따라 바뀐다
- 결과 화면(`--open`)에는 틀리거나 일부만 맞은 서답형도 내 답·모범답안이 선택형과 같은 표에 나온다
- 자동 채점으로 바꾸기 전에 낸 답('채점 대기')은 편집기에서 `서답형자동채점_기존제출` 을 한 번 실행하면 채점된다 ("(1) …" · "1. …" · 줄바꿈 · 칸별 단어 수로 나눈다. 못 나누면 그대로 두고 로그에 남긴다)
- 학생 답을 확인할 때 시트 전체가 필요하면 Drive 도구 `download_file_content` 에 xlsx 로 받아 openpyxl 로 연다 (`read_file_content` 는 앞부분 표본만 준다)

결과 화면 피드백(점수 구간별 한마디 · 더 노력할 부분)은 시험마다 만들 것이 없다 — 서버가 채점키의 유형으로 알아서 계산한다. 문구는 `Code.gs` 의 `FB_BANDS`(인터넷 말투, 선생님이 정한 문구 그대로) · `FB_TIPS`(담담한 말투) 에만 있다. 문구를 바꿔 달라는 요청이면 거기만 고치고 재배포를 안내한다.

**코드를 고쳤을 때 배포 (2026-10-01~ clasp)** — 선생님께 복사·붙여넣기를 부탁하지 않는다:
```
py 공용/온라인채점/설치.py 재배포
```
학생 링크 주소는 그대로다. 새 구글 서비스(권한)를 쓰는 코드를 넣었으면 선생님께 시트 메뉴에서 아무 항목이나 한 번 눌러 권한을 승인해 달라고 한다 — 승인 전에는 학생 제출이 막힐 수 있다. 로그인이 풀렸으면(`clasp login`) 선생님 브라우저 허용이 필요하다.

이 스킬은 `apps_script/` 코드를 고치지 않는다. 화면이나 채점 방식을 바꿔 달라는 요청이면 코드를 고친 뒤 README 끝의 재배포 절차를 사용자에게 안내한다.
