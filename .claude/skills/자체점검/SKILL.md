# 자체 점검

**자료를 만들면 반드시 이걸 돌린 뒤에 전달한다.** 예외 없다.

**공용 빌더(`공용/build/모의고사` · `단어장` · `변형문제` · `단어시험지`)로 만든 자료는 아래 공통 항목 대부분을 빌더가 이미 돌렸다** — 결함이 있으면 PDF가 안 나온다. 그 경우 빌더 출력의 "결함 0"을 보고에 옮기고, 빌더가 안 보는 것(각 README "자동으로 하는 점검" 밖)과 6번 렌더 육안 확인만 더 한다.

원칙은 하나다 — **눈으로 훑지 말고 프로그램으로 대조한다.** 정답 누출, 인용 중복, 페이지 잘림은 사람 눈으로 안 잡힌다. 실제로 워크북 검증에서 이 방식으로 20건 넘게 잡았고, 그중 절반 이상은 육안 검토를 두 번 통과한 것이었다.

## 어떤 자료든 공통으로 보는 것

### 1. 원문 대조
만든 자료의 지문·예문이 원문과 글자 단위로 같은지 전수 대조한다.
따옴표·대시·공백을 정규화(`norm()`)한 뒤 부분 문자열로 확인한다. 한 문장이라도 안 붙으면 보고한다.
**문항용 빈칸을 정답으로 되돌린 데는 예외로 두되, 어디를 어떻게 바꿨는지 표로 남긴다.**

### 2. 정답 누출
한 문항이 다른 문항의 답을 주면 안 된다. 이게 가장 많이 나는 사고다.
- 앞에서 뜻을 쓴 단어가 뒤 객관식 정답인가
- 선택형 지문·보기가 서답형 모범답안을 문장째로 주는가
- 사례 판정의 개념문에 글의 결론이 들어가 있는가
- T·F 진술문이 빈칸 정답에 기대고 있는가 — 빈칸이 비어 있으면 판정 불가다
- 함축 밑줄과 서답형 밑줄이 같은 곳인가

**학생 가시 요소만 검사한다.** 지문·발문·조건·선택지·T/F 진술문·사례 개념과 보기가 대상이다.
해설·모범답안·채점기준은 교사용이라 겹쳐도 결함이 아니다. 이 구분을 먼저 세워야 헛수고를 안 한다.

### 3. 인용 조건
"연속 3단어 이상 인용 금지" 같은 조건이 붙은 서답형은 **모범답안부터 그 조건을 지켜야 한다.**
모범답안과 지문의 3-gram 교집합을 프로그램으로 구한다. 눈으로는 절대 못 잡는다.

### 4. 문항 수와 배점
- 총 문항 수가 규격과 맞는가
- 배점 합이 만점과 맞는가
- 문항 번호가 연속인가
- 정답 번호가 한쪽에 몰리거나 순서대로 흐르지 않는가

선택지를 회전시켰다면 **해설의 ①~⑤도 같이 돌아갔는지** 확인한다. 이걸 빠뜨려서 31문항 중 25문항이 틀어진 적이 있다.
회전 시 "②~⑤" 같은 범위 표기는 의미가 깨진다 — 명시 열거로 바꾼다.

### 5. 학생 가시 요소에 강사용 멘트
`~하세요` `판서` `채점하면` `학생이` 를 학생용 파일에서 검색한다. 하나라도 나오면 고친다.
`자리` 라는 단어도 검색한다 — 문법 용어(부사 자리, 원급 자리)가 아니면 고친다.

### 5-1. 글쓰기 규칙 (`공용/규칙/글쓰기.md`)
**배부 자료에는 걸지 않는다.** 실전모의고사와 「영문 지문 분석 및 번역 모음」은 답지 해설까지 예외로 지정돼 있고, 나머지 배부 자료는 아직 정해지지 않았다. **묻지 않고 걸어서 빌드를 막지 않는다.**

`분석/출제경향.md` 같은 강사용 문서를 쓸 때만 그 파일을 따른다. 검사 도구는 `checks.writing_ko()` 지만 지금 어느 빌더도 부르지 않는다.

### 6. PDF 실물
반드시 렌더해서 본다. 코드만 봐서는 안 보인다.

```
pdftoppm -jpeg -r 80 out.pdf p   → Read 로 이미지 확인
```

프로그램으로 확인할 것:
- 빈 페이지 / 아래쪽이 30% 넘게 비는 페이지
- 한 문장이나 표 행이 페이지 경계에서 쪼개졌는지 — 문장 문자열이 **한 페이지 안에 통째로** 들어 있어야 한다
- 구획 헤더가 페이지 맨 끝에 혼자 남았는지
- 문항용 표시 잔재 (`___`, `@@`, `<u>`, `&amp;`, `①` 등)
- 선택지 번호가 두 번 찍혔는지 (`① ① …`) — 어법 밑줄 문항에서 선택지에 지문 표시를 붙이면 생긴다
- 지문의 빈칸·`( A )`·ⓐ 기호마다 **그것을 묻는 문항이 있는지** — 다른 회차 지문을 가져오면 묻지 않는 빈칸이 남는다

### 7. 답지와 본문 일치
답지 문항 번호가 본문과 같은가. 배치가 같은가(대조 채점을 위해). 정답 개수가 문항 수와 같은가.

## 자료 유형별로 더 보는 것

**단어 시험지** — 출제 범위 이탈, 표제어 중복(파트 내·간), 복수정답 누락, 유의어·반의어가 교재 단어장과 일치하는지, A형과 같은 번호·같은 유형인지, 교재 순서를 연속 3개 이상 따라가는지.

**학교 규격 시험지** — 학교 고정 순서를 지켰는지, 배점 구성(3점 몇 개·4점 몇 개)이 맞는지, 배점 0인 유형(한솔고 순서배열·문장삽입)을 넣지 않았는지. 그리고 아래 다섯 가지. 빌드 점검 "결함 0"으로는 하나도 안 잡힌다 — 나성중3 3·4회가 결함 0으로 나가서 강사에게 복수정답 4건, 풀 수 없는 문항 2건이 잡혔다(2026-09-18).
- **발문 유형·선택지 언어가 그 학교 기출 원본과 같은가.** 분석 문서의 요약("5점 = 추론·설명")만 보고 만들지 않는다. 기출에 없는 발문(함축·심경·의도 등)이나 선택지 언어(한국어 선택지 등)를 쓰지 않는다. 학교별로 확인된 것은 `공용/build/학교/<학교>.json` 에 넣어 빌더가 막게 한다(예: `options_no_hangul`)
- **오답 선택지가 추론이나 다른 해석으로 참이 되지 않는가** — 문항마다 직접 풀어 본다. 배열 문항은 다른 어순이 가능한지, 유의어 문항은 다른 선택지도 사전상 유의어인지 본다
- **정답 판정 근거가 학생에게 주어졌는가** — 영영풀이에 표제어가 없거나, 빈칸이 채워져야 참·거짓이 갈리면 풀 수 없다
- **근거가 그 문항의 지문 안에 있는가** — 앞 지문을 기억해야 풀리면 안 된다
- **답지 해설에 제작 메모가 없는가** — "(…바꿨다.)" 같은 출제 과정 설명은 해설이 아니다

완성 후에는 **만든 세션과 분리된 `검증` 에이전트에게 전 문항을 직접 풀게** 한다.

**워크북·변형문제** — 1권에서 이미 쓴 문항과 겹치는지, 밑줄이 서로 겹치는지, 사례 판정 정답이 특정 기호에 몰렸는지.

**본문분석·해석** — 영·한 문장 수가 맞는지, 해석 누락이 있는지, 문장 번호가 다른 자료와 같은지.

## 보고 형식

```
총 27지문 / 289문장 / PDF 47쪽
결함 0

(결함이 있으면)
결함 3건
  [정답누출] T3-2 ⑤ ⓐ가 ⑥ A형 답 그 자체
  [인용] T3-1 ⑥ 모범답안이 지문과 3단어 연쇄 일치 — "to a newer"
  [PDF] 37쪽 거의 빈 페이지
```

**결함이 0이 될 때까지 고치고 다시 돌린다.** 결함을 안고 전달하지 않는다.
고칠 수 없는 것(예: 원본 자료 자체의 오식)은 결함으로 보고하되, 왜 그대로 두는지 한 줄로 적는다.
