# 글쓰기 규칙

내가 쓰는 우리말 문장에 적용한다. **남이 쓴 글과 학교 형식을 따라야 하는 칸에는 적용하지 않는다.**

## 어디에 적용하나

| 적용한다 | 적용하지 않는다 |
|---|---|
| **내신결과 분석 피드백** — 시험총평·개별피드백 (`행정/내신결과피드백/`) | 지문·선택지·보기 (원문 그대로) · 원문 인용 |
| `분석/출제경향.md` 등 강사용 문서 | **발문** — 학교 기출 형식을 그대로 쓴다 (`다음 글의 요지로 가장 적절한 것은?`) |
| 수업안 · 수업일지 · 학생 기록 | 피드백 문서의 **기출분석 표** (칸이 명사구·숫자다) |
| 스킬·규칙 문서 | **실전모의고사·학교 규격 시험지 문서 전체** — 답지 해설까지 (2026-09-23 지정) |
| 세션에서 사용자에게 하는 답변 | **「영문 지문 분석 및 번역 모음」 문서 전체** — 번역문도 분석 칸도 (2026-09-23 지정) |
| | 단어 뜻풀이 · 영영풀이 (사전 형태를 따른다) |
| | **주간보고서 기입용 칸** — 실제 양식이 명사형이다 |
| | 표 머리 · 제목 · 차례 · 파일명 (명사구) |

**학생에게 나가는 자료는 예외 쪽에 가깝다.** 지금까지 예외로 지정된 것은 실전모의고사와 번역 모음이다.
**학생별 약점 보완 자료(`약점보완` 스킬 · `공용/build/약점보완`, 모든 반)의 설명 글에는 적용한다** (2026-09-29 지정). 그 안에 실은 실전모의고사 문항과 답지 해설은 원래대로 예외다.
새로 만드는 배부 자료에 이 규칙을 걸기 전에 **먼저 묻는다.** 묻지 않고 걸어서 빌드를 막지 않는다.

경계가 헷갈리면 **원문·양식 쪽을 살린다.** 문체 규칙이 정확성이나 학교 형식보다 앞서지 않는다.

## 어휘

1. **"자리"를 쓰지 않는다.** "지점", "여기", "데"로 바꾸거나, 바꿀 수 없으면 문장을 다시 짠다.
   **문법 용어는 예외다** — 부사 자리, 원급 자리, 목적어가 빠진 자리. 빌드 검사도 이 예외를 둔다.
2. **영어 관용구를 직역한 비유를 쓰지 않는다.** 아래는 예시이지 닫힌 목록이 아니다.

   | 쓰지 않는다 | 쓴다 |
   |---|---|
   | 깔아 둔다 | 먼저 제시한다 |
   | 각도를 잡는다 | 관점을 정한다 |
   | 축 | 중심 논지 |
   | 한 걸음 더 나아간다 | 더 나아간다 |
   | 손대지 않는다 | 다루지 않는다 |
   | 명제를 세운다 | 명제를 제시한다 |
   | 다음 장에 넘긴다 | 다음 장으로 이어진다 |

   "수치 하나를 더 놓으면", "이 계산에는 이름이 있다", "한 가지 그림으로 남겼다"도 같은 종류다.
   다만 **"축"이 좌표축·시간 축을 가리킬 때는 그대로 쓴다.** 낱말이 아니라 비유인지가 기준이다.
3. **직역투를 쓰지 않는다.** "여덟 걸음" → "여덟 단계".
4. **긍정인지 부정인지 드러나지 않는 말을 쓰지 않는다.** "열심이 만들어 낸 것" → "열심 덕분에 얻은 것" 또는 "열심 때문에 잃은 것". 사회의 경쟁을 "경주"로 쓰지 않는다.
   단, **관찰을 적는 곳(수업일지 학생 기록·출제경향)에서 근거 없는 가치 판단을 붙이지 않는다.** 여기서는 본 것을 그대로 적는다.

## 문장

5. **한 문장에 "것"을 두 번 이상 쓰지 않는다.** "~다는 것을 보인다" → "~임을 드러낸다".
6. **행위자가 없는 피동문을 쓰지 않는다.** "설명된다" → "설명할 수 있다", "여겨진다" → "여긴다".
   **문법 서술은 예외다** — "to부정사가 목적격보어로 쓰였다", "수동태로 쓰인다". 여기서 능동으로 바꾸면 주어가 달라져 뜻이 틀어진다.
   **행위자가 뻔한 관용 표현도 예외다** — "새 유형이 출제되었습니다"(낸 곳은 학교다), "시험이 치러졌습니다".
   **학생의 잘못을 눅여 말할 때도 예외다** — "실수가 반복되었습니다"를 "실수를 반복했습니다"로 바꾸지 않는다. 학부모가 읽는 글에서 학생을 탓하는 말투가 된다 (2026-09-23 지정).
7. **주어와 목적어를 생략하지 않는다.** 무엇이 무엇을 하는지 문장 안에서 드러나게 쓴다.
8. **추상 명사를 사람처럼 주어로 세우지 않는다.** "성적표가 항목을 얻는다".
9. **관형절의 동사가 뒤의 명사를 받지 못하는 꼴을 쓰지 않는다.** "드린 날", "채운 새벽" → "나온 날".
10. **동사를 "-음"으로 명사로 만들지 않는다.** "그 받음에는".
11. **주어가 다른 두 서술이나, 사실 서술과 글쓴이의 평가를 "-고", "-아서"로 한 문장에 잇지 않는다.**
12. **물건을 올려놓는 비유를 쓰지 않는다.** "목록 위에 있다" → "같은 목록에 들어 있다".
13. **한 절 안에서 같은 명사를 거듭 쓰지 않는다.**
14. **사람을 "한 연구자", "한 신학자"처럼 돌려 부르지 않는다. 이름을 쓴다.**
    **출처에 이름이 있을 때만이다.** 지문이 `A researcher found…`로만 쓴 인물은 이름을 지어내지 않고 원문대로 둔다.
    연구가 익명으로 처리한 참여자는 익명 그대로 둔다.
    **학생 이름은 문서마다 다르다** — 배부 자료와 주간보고서 기입용 칸에는 넣지 않는다. 내신결과 피드백은 그 학생에게 가는 글이므로 이름을 쓴다(`연우는…`).

> 사용자가 준 원래 목록에는 5~8번이 없었다. 여기서 1~14로 다시 매겼다.

## 어떻게 검사하나

**지금 어느 빌더도 이 규칙을 걸지 않는다.** 배부 자료는 전부 예외이거나 아직 정해지지 않았다.
빌더가 보는 것은 전부터 있던 `jari()`("자리")와 `teacher_words()`(강사용 멘트)뿐이다.

**도구는 있다** — `공용/build/core/checks.py` 의 `writing_ko(rep, where, s)`.

| 규칙 | 잡는 방법 |
|---|---|
| 1 자리 | `jari()` — 문법 용어 앞에 붙은 것만 통과 |
| 2 비유 | 고정 표현 목록 대조 |
| 5 "것" 두 번 | 한 문장 안 횟수 |
| 6 피동 | `설명된다`·`여겨진다`·`보여진다` 류 목록 |
| 10 "-음" | 참고로만 알린다 (`다음`·`처음`처럼 원래 명사인 것이 많아 빌드를 막지 않는다) |

**쓰려면 사용자에게 먼저 묻는다.** 그리고 해설·설명 글에만 건다 — 지문·발문·선택지에 걸면 발문("가장 적절한 것은?")이 5번에 잡힌다.
학생 가시 요소에는 지금까지처럼 `jari()` 와 `teacher_words()` 만 건다.

**눈으로 보는 것** — 3·4·7·8·9·11·12·13·14. `자체점검` 스킬과 `검증` 에이전트의 점검 항목에 들어 있다.
